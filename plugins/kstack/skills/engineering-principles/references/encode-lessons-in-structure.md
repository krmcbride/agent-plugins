# Encode Lessons in Structure

When you catch yourself writing the same instruction a second time, or notice a recurring correction, encode the rule as structure instead of more text: architecture that makes the mistake impossible, a type, a lint whose error names the fix, a runtime check, a test, or a script. Prove the check fails on a real instance of the mistake.

If the lesson needs judgment and cannot be encoded, make the instruction more prominent and add an example of the failure.

**Corollary:** if the fix is structural, use only the structural fix. The instruction is the symptom.
